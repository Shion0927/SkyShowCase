# AI天気通知アプリ｜設計メモ

## 🎯 目的
- 人によって違う  
  「雨・寒さ・暑さが嫌」「この時間・この場所で知りたい」  
  を学習し、**間に合う・うるさくない通知**を出す。

---

## 🧠 基本方針
- 通知は **価値が高いときだけ**
- **学習（自動）＋固定ルール（手動）** を両立
- 「欲しかったのに届かなかった」を検知・修正する
- 位置情報は **最小限・理由を明確に**

---


## 📱 体験設計（通知 / Apple Watch / iPhone）

### 役割分担（この一文で説明できるように）
- **通知 / Apple Watch：判断する場所**（一瞬で見て行動できる結論）
- **iPhoneアプリ：納得して育てる場所**（理由・履歴・設定・学習）

### Apple Watch対応で伸びる価値
- **通知が主役の設計と相性が良い**：スマホを開くほどではないが、見逃したくない情報を腕で即判断できる
- **行動の直前に届く**：外に出る／移動開始／駅に着く等のタイミングで価値が最大化する
- **コンプリケーションが強い**：受動的に目に入るので“毎日使う”導線になる

#### Watchで提供する最小セット（おすすめ）
- **通知（最優先）**：短文で「何が起きる + どうする」
- **ミニ画面（閲覧 + 1タップ評価）**：今日の重要カード／次イベントまでの残り時間／👍👎（学習用）
- **コンプリケーション（できれば）**：雨まであと○分、次の注意イベントまでのカウントダウン等

> Watch側は「詳細表示」よりも **“結論 + 反応（学習）”** に寄せる。

### iPhoneアプリを「開く価値がある」ものにする中身
通知だけだと「アプリとしての中身が薄い」問題が出るので、iPhoneは **“裏側の可視化”** を担当させる。

#### iPhoneで見せると強いもの（情報量は増やさず価値を増やす）
- **通知ログ**：送った／送らなかった通知（抑制も含む）の一覧
- **理由の説明**：「なぜ今送ったか」「なぜ黙ったか」（信頼の装置）
- **学習の可視化**：最近の傾向、しきい値の推定、調整履歴（“自分専用になっていく感覚”）
- **固定ルール（Pinned）**：AI任せだと不安な部分をユーザーが固定できる（例：雨は必ず通知、朝は通知しない等）
- **通知では聞けない問い**の受け皿：境界ケースのカード、Regret、通知頻度の相談

#### iPhoneの最小UI案（MVPでも成立）
- **Home**：今日の結論カード（1〜2） + 通知ログ（今日分）
- **Timeline**：短期（時間別）と中期（日別）の要点（重要変化だけ強調）
- **You**：しきい値／固定ルール／学習状況／通知回数と抑制回数


## 🔔 通知判断モデル（2段階）

### 1️⃣ 不快度（天気そのもの）
カテゴリ別に個人しきい値を持つ：
- 雨：降水確率 / 降水量 / 開始時刻
- 寒さ：気温 / 体感温度
- 暑さ：気温 / 体感 / 湿度
- 風・警報など

→ 反応ログでしきい値を微調整

---

### 2️⃣ 通知価値（今送るべきか）
- 不快度
- 時刻（朝 / 昼 / 夕 / 夜）
- 曜日（平日 / 休日）
- 最近の通知疲れ
- 場所（職場にいる / 自宅にいる）

→  
**Hard通知 / Soft通知 / In-appのみ / 送らない** を決定

---

## 🧩 「欲しかったのに届かなかった」対策

### 観測できない問題への解法
1. **後悔（regret）取得**
   - 通知しなかったイベント後、アプリ内で  
     「さっきの雨、知りたかった？」（1タップ）
2. **代理シグナル**
   - 通知なしでも予報 / レーダーを自発的に確認
3. **探索（exploration）**
   - 境界イベントを低頻度・弱通知で試す

---

### ── Regret（「欲しかった？」）設計（低頻度・高効率） ──

#### 基本方針
- 毎回は聞かない
- **不確実なときだけ聞く**
- 暗黙シグナルを主役、regret は補助

#### Regret を出す価値が高いタイミング
1. **境界ケース**
   - 通知確率 0.45〜0.55
   - しきい値（例：雨50%）の前後
2. **取りこぼし疑い**
   - 通知なしで予報 / レーダーを見に来た
3. **学習が不安定な時期**
   - 新規ユーザー初期
   - 無視・即消しが急増した直後

#### 出さないケース
- 判断確信度が高い
- 最近すでに質問している
- 「質問を表示しない」が有効
- 学習が十分に収束

#### 頻度ガードレール
- 週 最大 **1〜2回**
- 同カテゴリ（月）で数回まで
- 直近から **最低7日空ける**
- 同日に複数回出さない

#### UI / UX
- 通知では聞かない
- アプリ起動時の小さなカードのみ
- 1タップ：
  - 👍 欲しかった
  - 😐 どっちでも
  - 👎 いらなかった
- スワイプで即消し／「今後表示しない」あり

---

## 🏠 自宅・職場 × 出勤・帰宅通知

### 位置情報の扱い
- ユーザーが **自宅 / 職場を明示設定**
- ジオフェンス（半径200–500m）
- 常時GPS追跡はしない

### 権限戦略
1. While Using で開始
2. 価値体験後に Always を提案  
   （帰宅前に自動で雨を知らせるため）

---

## ⏰ 帰宅時の雨通知（遅れない設計）

### メイン：出る前通知
- 帰宅時間帯（例 17:30–20:00）
- **開始30–90分前**に判定
- 帰宅枠に雨が来る見込みなら通知

例：
> 「18–20時に雨の可能性。傘を持って出ると安心」

### 補助：職場 exit 後（保険）
- exit後 15–45分以内に雨が始まる場合のみ
- 行動可能な内容に限定
- クールダウン強め

---

## 🔄 環境変化への対応
- 学習に **時間減衰**（直近重視）
- 無視・即消し急増 → 変化検知
  - 通知頻度↓ / 探索↑
- 「この時間帯で通知してほしい」を  
  **1タップで固定（PinnedRule）**

---

## 🛑 スパム防止
- 1日上限
- カテゴリ別クールダウン
- 弱い事象は In-app のみ
- 嫌がられているカテゴリは自動でしきい値UP
